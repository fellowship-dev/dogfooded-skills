# Real workload acceptance

This bundle is instruction packaging. Text-search assertions cannot show that an agent selected the right project, stayed within scope or delivered useful copy. No such tests substitute for behavioral evidence. Existing seo-ops transport/static tests remain owned by that skill; no second crawler or duplicate test harness is introduced here.

Before a PR, run this draft bundle at least five times against real workloads using the host's existing evaluation/session mechanism. `cases.json` is a workload/rubric manifest, not a claim of execution. Supply actual site URLs, retained first-party evidence and approved scope privately at runtime. Never add private contexts, paid raw responses or customer data to this public directory.

1. Evaluate the draft `seo-workflows` and `seo-ops` together before publishing the contribution. Record the resolved development paths, base revision and exact candidate file/tree hashes. A development install is draft evidence, not an accepted consumer pin. After draft acceptance, publish the reviewed revision and verify both clean consumers through their supported source/ref/hash mechanism; no imports through an unrelated checkout. Keep published consumer pins unchanged until acceptance.
2. Run the five mandatory site workloads: authorized growth, ordinary maintenance, missing measurement, intentional exclusion and pending retirement. Bind each run explicitly to only that site's approved inputs and evidence. Record model/agent/runtime, prompt, tools available, actual tool calls, output artifacts, time, operations and costs. Separate contexts are useful isolation when available; explicit site boundaries and complete retained traces remain required. Real refusal evidence is a supplemental boundary case; synthetic variants may supplement but do not count as five real workloads.
3. Independently review the complete output and call trace against every required outcome in its case. Assess the utility of the actual copy/link recommendation, not the presence of words in the instructions. Compare with the current consumer workflow when replacement benefit is claimed; record what got better, stayed equal or regressed.
4. Keep one private receipt per run: case ID, actual workload/source/date, candidate revision/install hash, input/artifact/call-trace paths and hashes, criterion verdicts with evidence, reviewer, failure/correction and final verdict. Preserve failures; reruns retain lineage. Missing access may prove graceful degradation but cannot prove successful publication or measured outcomes.
5. Accept the draft contribution only when five real site runs have evidence-backed verdicts, all critical scope/privacy/identity controls pass, all five stages are exercised, and complete deliverable/report quality is independently reviewed. Include actual benchmark results and receipt links in the PR; never claim pending runs passed. Consumer live acceptance and publication remain separate gates.

Cases can reuse the same intervention receipts across weekly/monthly views. Tests do not grant new paid calls, OAuth, production publication, deletion or account changes. If a required real workload is unavailable, label acceptance pending and identify it precisely.
