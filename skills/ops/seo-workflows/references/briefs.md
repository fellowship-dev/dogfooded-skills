# Briefs and complete content stage

1. Require authorized growth/content work and site-approved facts, audience, language, goal and editorial/release owner. Read the selected opportunity and evidence from keywords/audit/links; do not buy research to fill a template. Maintenance does not enter this stage.
2. Inspect the current page and retain its title, intro, main copy, relevant links and baseline receipt. For a proposed new URL inspect adjacent pages to avoid overlapping intent. Record the specific user question, page purpose, differentiated answer, intended action and trustworthy support. Clearly separate verified claims from hypotheses and unanswered factual questions.
3. Deliver the actual reviewable change, not only an outline. Match the selected scope:

   | Intervention | Required artifact |
   |---|---|
   | Existing page | Exact before/after title and intro plus the complete revised sections or code diff |
   | New article/comparison | Complete ready-to-review copy, title/description, route, sources, contextual links and truthful CTA |
   | Useful tool | Bounded implementation and functional evidence from the existing site workflow |
   | Contextual links | Exact source edits and reader benefit under the links contract |

   Keep useful unchanged content. Do not invent testimonials, customers, product capabilities, measurements or structured data unsupported by visible content. If a necessary fact is unavailable, label the deliverable's blocked portion and the exact owner decision; do not call it ready to publish.
4. Use the site's normal implementation, checks and editorial review. Publication occurs only under its existing authorization. Retain baseline, artifact/diff, review result, deployment/publication receipt and actual date. Verify live page status, canonical, rendered copy and affected links after authorized publication. A draft or merged PR remains a draft/merge until that proof exists.
5. Record one intervention ID with its intended outcome and comparable follow-up window. Reports reuse this ID. Schedule/measurement setup requires its own existing authority; this stage does not create a recurring campaign.
