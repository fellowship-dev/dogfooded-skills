# Reports stage

1. Read retained intervention, publication and measurement receipts for the requested site and period. No collection, keyword purchases, publication, rank-tracker creation or rerun is initiated by report generation. Missing evidence becomes an explicit gap. Choose the report owner from the input contract: maintenance uses the site's existing renderer/manifest/completion path; growth uses its existing weekly/monthly adapter and archive.
2. Produce a short owner view: what improved/shipped, links to live work or reviewable drafts with accurate state, observed search/goal outcomes, unresolved obstacles, and the next justified action or owner decision. Link a technical appendix with affected URLs, methods, source revision, coverage, baseline/comparison, uncertainties and receipts. A cycle with no gain still reports delivery, losses and learning.
3. Weekly views count actual deliveries by intervention ID/publication date, separating drafts and holds. Monthly views reference those same IDs and compare explicit windows with the same source/query/market/device/search type and declared lag/completeness. Do not count regenerating a report as delivered work. If evidence is not comparable, explain why and defer the numeric comparison. Missing analytics is unavailable, never zero. Changes after publication are observations, not causal proof.
4. When a private OpenSEO save is authorized, read `list_report_templates` with `{"projectId":"PROJECT_ID"}` and follow the selected project-owned template. Do not create/modify templates automatically. Save with `save_report` using these exact supported fields:

   ```json
   {"projectId":"PROJECT_ID","title":"Weekly delivery — October 18, 2026","summary":"VERDICT, top action and verified numbers","html":"<!doctype html><html><head><title>Weekly delivery — October 18, 2026</title></head><body><h1>Weekly delivery — October 18, 2026</h1><p>REVIEWED REPORT CONTENT</p></body></html>","skill":"seo-workflows"}
   ```

   Replace all example report content and dates. Add `templateId` only when actually following that template. HTML must be a complete self-contained document with inline CSS, no external requests/scripts, no backticks or dollar-brace sequences; aim under 80 KB. Keep title and h1 identical. Omit `reportId` for a new immutable-period report: supplying it overwrites the old content without history and requires separate explicit replacement authority. There is no visibility argument; saving is not a public-sharing grant. Do not invoke sharing tools.
5. Retain the returned report ID/URL and portable HTML in the site's existing archive. Verify saved contents with `get_report` using `{"projectId":"PROJECT_ID","reportId":"REPORT_ID","includeHtml":true}`. Check returned HTML bytes against `htmlBytes` before claiming a complete readback; a truncated response is unverified. A missing OpenSEO binding/save permission leaves a portable local report with the existing report owner; never create an account/project as a workaround. The report and appendix must remain audience-appropriate and site-separated.
